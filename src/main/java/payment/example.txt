Для тестирования платежей в песочнице WEBPAY вам не нужно тратить реальные деньги. Система предоставляет специальный тестовый контур (Sandbox), который полностью имитирует поведение реального банка.
Вот пошаговый гайд, как правильно провести тесты в вашем Java-приложении.
Шаг 1. Проверьте адреса (Эндпоинты) в коде
Убедитесь, что в ваших классах WebpayPaymentService и WebpayStatusChecker прописаны именно тестовые URL-адреса (в коде выше мы их уже настроили):
• Шлюз оплаты: https://webpay.by
• API статусов: https://webpay.by
• Параметр теста: В параметрах генерации ссылки обязательно должно передаваться "wsb_test" = "1".
Шаг 2. Запросите тестовые данные у поддержки
Если вы этого еще не сделали, напишите на support@webpay.by запрос:
«Добрый день! Подключаем десктопное приложение на Java. Просим предоставить тестовые доступы (Billing ID, Secret Key, а также логин и пароль для JSON API) для работы в Sandbox».
Вам пришлют тестовый wsb_storeid, тестовый ключ для генерации MD5-подписи и данные Basic-авторизации для проверки статусов. Вставьте их в переменные вашего менеджера.
Шаг 3. Используйте тестовые карты для симуляции разных сценариев
Когда ваше приложение сгенерирует ссылку и откроет браузер, WEBPAY покажет тестовую платежную страницу. Для проверки различных исходов (успех, отказ, ошибка) используйте официальные тестовые карты:
Сценарий теста	Номер карты	Срок действия	CVC	Ожидаемый статус в API
Успешная оплата	4242 4242 4242 4242	Любой в будущем (напр., 12/29)	111	completed / approved
Отказ (Недостаточно средств)	4111 1111 1111 1111	Любой в будущем	111	declined / failed
Ошибка (Неверный CVC/Срок)	Любая карта выше	Введите просроченный (напр., 01/22)	000	declined / failed
Шаг 4. Чек-лист для проверки в вашем приложении
Запустите программу и пройдите по трем главным сценариям, чтобы убедиться, что логика UI и потоков работает без багов:
1. Тест успешного пути (Happy Path):
	• Нажимаете «Купить» → Кнопка блокируется → Открывается браузер.
	• Вводите карту 4242... → Нажимаете «Оплатить».
	• Результат: В течение 5 секунд ваше Java-приложение должно само поймать статус completed, закрыть платежное окно и выдать сообщение: «Спасибо за покупку!».
2. Тест принудительной отмены:
	• Нажимаете «Купить» → Открывается браузер.
	• Не вводя карту в браузере, закрываете окно ожидания в вашем Java-приложении на «крестик».
	• Результат: В консоли должно появиться сообщение об остановке трекера. Браузер можно закрыть вручную. Приложение не должно зависнуть или вылететь, кнопка покупки снова становится активной.
3. Тест таймаута (для проверки ограничений):
	• В классе WebpayStatusChecker временно измените MAX_WAIT_MINUTES на 1 (одна минута), чтобы не ждать долго.
	• Нажимаете «Купить» → Открывается браузер.
	• Ничего не делайте в течение 1 минуты.
	• Результат: Ровно через минуту Java-приложение должно прервать опрос и вывести ошибку: «Время сессии оплаты истекло».
Переход на боевую среду (Продакшен)
Как только все три теста отработают идеально, для запуска реальных продаж вам останется сделать всего три действия:
1. Поменять в коде PAYMENT_GATEWAY_URL на https://webpay.by.
2. Поменять API_STATUS_URL на https://webpay.by (или адрес, который укажет поддержка в боевом аккаунте).
3. Изменить параметр "wsb_test" с "1" на "0".
4. Заменить тестовые ключи и логины на реальные, которые WEBPAY выдаст после подписания договора.
